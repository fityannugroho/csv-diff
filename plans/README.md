## Findings considered and rejected

- **Directory-as-output "silent rename" (was plan 002) — FALSE POSITIVE,
  rejected**: click ≥ 8.0 (installed 8.4.2) validates `file_okay`/`dir_okay`
  whenever the path exists, regardless of `exists`; the CLI already rejects
  directories with a clear message and the existing test passes. The audit
  claim to the contrary was wrong.

- **C2 — diff on normalized re-serialized rows hides quote-only differences /
  can't reconstruct file2 (`utils/csv.py:69,75`, `cli.py:114`)**: real
  correctness concern, but it is a *contract* decision (data-level vs
  byte-level diffing), not a mechanical fix. Deferred into plan 005's evidence
  request (the spike must state whether a raw-line path fixes it) and the
  follow-up migration plan.
- **C9 — TOCTOU symlink race between `validate_output_path` and file creation
  (`validation.py:75-91`, `files.py:39-54`)**: real window, but requires a
  local concurrent adversary in CWD of a single-user CLI — LOW impact. The
  `files.py` guard added in plan 002 (directory check before open) is a small
  hardening step in the same seam; a full dir-fd/`O_NOFOLLOW` fix is not worth
  the complexity for this threat model. Revisit only if the CLI gains a
  server-side/remote input surface.
- **C8 — non-UTF8 files take an extra full-copy pass; 8KB probe can misdetect
  (`csv.py:28,52-66`)**: folded into plan 005's scope (the spike measures the
  read path end-to-end; a stdlib path eliminates the copy for cp1252 too).
- **C10 — stale published docs/examples/skill show relative diff headers
  (`cli.py:114` vs README/SKILL/result.diff)**: real, cheap, but doc-only;
  not selected for the current batch. Note: plan 001 touches the same
  README/SKILL files and adds its limitation line next to these sections —
  if a later maintenance pass wants C10, do it together with that.
- **C11 header-only CSV aborts "contains no data"**: LOW confidence the
  current behavior is wrong (message wording suggests intent); requires a
  product decision on whether header-only files are "empty". Not worth doing
  without that decision.
- **C12 BOM heuristic misdetects cp1252 "ÿþ" (UTF-16 signature)**: extremely
  rare input class; LOW confidence of real-world occurrence. Only worth fixing
  alongside the read-path migration (plan 005 outcome).
- **C13 test-quality (vacuous identical-files assertion, message coupling,
  global-chdir fixture)**: real, but the `in_tmp_path` fixture is load-bearing
  across test_cli.py; restructuring it has its own risk. Deferred; the
  identical-files assertion is revisited naturally when plan 001's rejection
  tests land in the same file.
- **C14 `compare()` god function (`cli.py:37-149`)**: structural debt; the
  current batch deliberately keeps changes surgical. A refactor would touch
  every plan's merge surface — revisit after 001-005 land.
- **C1 duplicate-report note**: both audit reviewers surfaced the embedded
  newline bug; consolidated into plan 001.
- **C9 duplicate-report note**: both audit reviewers surfaced the TOCTOU
  window; consolidated into this "considered and rejected" entry.
